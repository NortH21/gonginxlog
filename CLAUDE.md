# CLAUDE.md

Контекст для Claude Code при работе в этом репозитории. Загружается
автоматически в начале каждой сессии — сюда вынесено то, что нужно
знать сразу, не перечитывая всю историю разработки.

## Что это

`gonginxlog` — CLI на Go для парсинга nginx access-логов по реальной
директиве `log_format` (а не по жёстко заданному regex): фильтры,
агрегированный отчёт в стиле goaccess, и живой TUI-дашборд в стиле k9s
(`--ui`) с детекцией аномалий.

Репозиторий: `github.com/north21/gonginxlog` (публичный, GitHub Actions
пушит образы в ghcr.io + опционально Docker Hub, и релизные бинарники
на GitHub Releases).

## Где что искать

- **`README.md`** (на русском) — пользовательская документация: флаги,
  примеры, `--ui`, Docker, релизы.
- **`DESIGN.md`** (на английском, для контрибьюторов) — архитектурные
  решения и их обоснование, структура пакетов, известные компромиссы.
  **Читай его перед существенными изменениями** — там уже разобраны
  причины большинства неочевидных решений (например, почему
  `--nginx-conf` без нужного `log_format` — это ошибка, а не тихий
  фоллбэк; почему детекция аномалий бакетит по времени записи, но
  вытесняет по wall-clock времени).
- **Этот файл** — краткий снимок статуса и правил для будущих сессий.

## Правило поддержки документации

При изменении пользовательского поведения (флаги, вывод, форматы) или
архитектуры — обновляй **все три файла** в одном изменении:
`README.md` (примеры, на русском), `DESIGN.md` (обоснование, на
английском) и этот файл, если изменился общий статус проекта. Это
явное требование пользователя, не предложение.

## Текущий статус (актуализировано 2026-08-13)

Реализовано и опубликовано:

- Парсинг `log_format` — и JSON (`escape=json`), и обычные форматы через
  генерируемый regex; чтение из реального `nginx.conf` с рекурсивными
  `include`.
- Фильтры: `--since`/`--until`/`--last`, `--status`, `--ip`,
  `--country`, `--grep`, `--field`.
- Batch-отчёт: топ IP/путей/стран, коды статусов (цветные в терминале),
  перцентили таймингов, авто-гистограмма по времени; текст или `--json`.
  Top UA/referer — опционально, флаги `--show-agents`/`--show-referers`
  (по умолчанию скрыты).
- `--routes-file` (YAML) группирует пути в ограниченный набор
  "маршрутов" по regex — решает проблему кардинальности сырых путей
  (`/counter?id=...`); добавляет секцию "Slowest routes" (средний
  request_time по маршруту, не перцентили — см. DESIGN.md).
- Многофайловый/gzip/stdin вход, `-f`/`--follow`.
- Docker-образ (multi-arch, ~6МБ) и GitHub Release с бинарниками — оба
  через GitHub Actions (`.github/workflows/docker.yml`,
  `release.yml` + goreleaser).
- Live TUI-дашборд (`--ui`): переключаемые виды (число видов зависит от
  конфига — countries/agents/referers/routes показываются только когда
  применимо), фильтр `/` (свой мини-язык, см.
  `internal/tui/filter_dsl.go`), drill-down по `Enter` (с обрезкой
  длинных значений в таблицах и полным значением в drill-down),
  детекция аномалий (`internal/anomaly`) с бейджем в хедере; пороги
  настраиваются флагами `--anomaly-*`, дефолты пересчитаны с 0.30/20 на
  0.60/100 после двух реальных ложных срабатываний ip_flood (см.
  DESIGN.md). Хедер показывает версию сборки; `p` ставит
  live-обновление на паузу без остановки сбора данных (только live).
  **Live vs static**: `--ui` живой только для ровно одного обычного
  файла; несколько файлов, `.gz`, или явный `--ui-static` — статичный
  просмотр (без тейлинга и без фоновой нагрузки вообще, см. DESIGN.md).

Внешние зависимости: `github.com/rivo/tview` (+ `gdamore/tcell`, ради
`--ui`) и `go.yaml.in/yaml/v3` (ради `--routes-file`) — **не**
`gopkg.in/yaml.v3`, тот путь не обновлялся с 2022. До `tview` проект
был чистым stdlib.

Санитайзинг вывода (`internal/term.Sanitize` + `tview.Escape` через
`safeCellText` в `internal/tui/views.go`): все поля из лога (путь, UA,
referer, сырая строка) — это данные, которые полностью контролирует
HTTP-клиент. Перед печатью в терминал/TUI они всегда очищаются от
управляющих байт и от tview-разметки (`[tag]`) — не флаг, всегда
включено. Подробности и почему это нельзя было доверить экранированию
на стороне nginx — см. DESIGN.md, раздел "Terminal / tview injection
hardening".

**Не начато, только обсуждено (2026-08-12)**: Prometheus-экспортер на
базе логов — только гео + аномалии из `internal/anomaly` (базовые
метрики запросов/статусов уже покрывает `nginx-module-vts` у
пользователя, дублировать не нужно). Полный разбор — путь/IP
кардинальность, схема ротации логов, почему это не нагрузит диск/CPU —
в `DESIGN.md`, раздел "Idea: log-based Prometheus exporter". Пользователь
сказал, что вернётся к этому отдельно — не начинать реализацию
самостоятельно, пока не попросят.

## Сборка и проверка

```sh
go build ./... && go vet ./... && gofmt -l . && go test ./...
```

- Docker: `docker build -t gonginxlog:local .`
- GoReleaser без публикации: `goreleaser release --snapshot --clean`
- Реальный тестовый лог лежит в `tests/*.log` — он в `.gitignore` (не
  коммитится, это реальные production-данные пользователя, ~430МБ).
- CI (`.github/workflows/test.yml`) гоняет тот же набор (`build && vet
  && gofmt -l . && go test ./... -race`) перед сборкой Docker-образа
  (`docker.yml`) и релиза (`release.yml`) — оба используют его как
  reusable workflow через `needs: test`, так что образ/бинарники не
  соберутся, если тесты красные.

## О чём легко забыть

- `internal/tui` визуально проверить в headless-среде нельзя (нет
  `/dev/tty`). Логика/переходы состояний проверяются через
  `tcell.SimulationScreen` (`internal/tui/app_smoke_test.go`) — но
  внешний вид, цвета и "чувство" интерфейса подтверждает только
  пользователь в своём терминале.
- **Любое изменение в `internal/tui` (и вообще там, где несколько
  горутин трогают общее состояние) проверяй через `go test ./... -race
  -count=10`, а не просто `go test ./...`.** Обычный запуск ничего не
  покажет — гонку по map поймал только `-race` (см. DESIGN.md, раздел
  про crash 2026-08-12: `Aggregator.Report()` отдавал живой алиас на
  внутреннюю map вместо копии, плюс `reseed` звал `Report()` без
  блокировки — оба бага были невидимы без `-race`, а в проде уронили
  процесс fatal-ошибкой Go-рантайма, не перехватываемой `recover()`).
- `--nginx-conf` без указанного `--format-name` в конфиге — это
  осознанная ошибка, а не фоллбэк на встроенный дефолт (см. DESIGN.md).
- Не пушить в `main` и не создавать релизные теги без явной просьбы —
  это отдельные, ранее явно запрошенные действия каждый раз.
- **Никаких реальных доменов/хостнейнов/IP из реальных логов в
  примерах, комментариях или коммитах — только `example.com`-плейсхолдеры.**
  Уже один раз пришлось переписывать всю историю git
  (`git filter-repo`) из-за пары реальных доменов, просочившихся в
  README/DESIGN, и заодно поменять email автора/коммиттера везде на
  `north21@users.noreply.github.com` (см. DESIGN.md, раздел про
  переписывание истории 2026-08-12). Это разовая чистка сделана, но
  правило постоянное — самопроверка "это не реальный домен?" перед
  коммитом примеров с логами.
- Локальный `git config user.email` пользователя всё ещё настоящий
  рабочий адрес — переписка истории это не трогала (только прошлые
  коммиты). Если новые коммиты в этом репо тоже должны идти с
  нейтральным email — это отдельная, явно не запрошенная пока правка
  `git config` (сам не делаю без спроса, см. правило про git config
  выше в системных инструкциях).
