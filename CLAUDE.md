# CLAUDE.md

Контекст для Claude Code при работе в этом репозитории. Загружается
автоматически в начале каждой сессии — сюда вынесено то, что нужно
знать сразу, не перечитывая всю историю разработки.

## Что это

`gonginxlog` — CLI на Go для парсинга nginx access-логов по реальной
директиве `log_format` (а не по жёстко заданному regex): фильтры,
агрегированный отчёт в стиле goaccess, и живой TUI-дашборд в стиле k9s
(`--ui`) с детекцией аномалий.

Репозиторий: `github.com/north21/gonginxlog` (публичный, GitHub Actions
пушит образы в ghcr.io + опционально Docker Hub, и релизные бинарники
на GitHub Releases).

## Где что искать

- **`README.md`** (на русском) — пользовательская документация: флаги,
  примеры, `--ui`, Docker, релизы.
- **`DESIGN.md`** (на английском, для контрибьюторов) — архитектурные
  решения и их обоснование, структура пакетов, известные компромиссы.
  **Читай его перед существенными изменениями** — там уже разобраны
  причины большинства неочевидных решений (например, почему
  `--nginx-conf` без нужного `log_format` — это ошибка, а не тихий
  фоллбэк; почему детекция аномалий бакетит по времени записи, но
  вытесняет по wall-clock времени).
- **Этот файл** — краткий снимок статуса и правил для будущих сессий.

## Правило поддержки документации

При изменении пользовательского поведения (флаги, вывод, форматы) или
архитектуры — обновляй **все три файла** в одном изменении:
`README.md` (примеры, на русском), `DESIGN.md` (обоснование, на
английском) и этот файл, если изменился общий статус проекта. Это
явное требование пользователя, не предложение.

## Текущий статус (актуализировано 2026-08-12)

Реализовано и опубликовано (теги v0.1.0, v0.2.0):

- Парсинг `log_format` — и JSON (`escape=json`), и обычные форматы через
  генерируемый regex; чтение из реального `nginx.conf` с рекурсивными
  `include`.
- Фильтры: `--since`/`--until`/`--last`, `--status`, `--ip`,
  `--country`, `--grep`, `--field`.
- Batch-отчёт: топ IP/путей/UA/referer'ов/стран, коды статусов,
  перцентили таймингов, авто-гистограмма по времени; текст или `--json`.
- Многофайловый/gzip/stdin вход, `-f`/`--follow`.
- Docker-образ (multi-arch, ~6МБ) и GitHub Release с бинарниками — оба
  через GitHub Actions (`.github/workflows/docker.yml`,
  `release.yml` + goreleaser).
- Live TUI-дашборд (`--ui`): переключаемые виды, фильтр `/` (свой
  мини-язык, см. `internal/tui/filter_dsl.go`), drill-down по `Enter`,
  детекция аномалий (`internal/anomaly`) с бейджем в хедере; пороги
  настраиваются флагами `--anomaly-*` (проверено и поправлено по
  фидбеку с реальных production-логов — см. DESIGN.md, раздел "Fixes
  and changes from real production use").

Первая и единственная внешняя зависимость — `github.com/rivo/tview`
(+ `gdamore/tcell`), добавлена ради `--ui`. До этого проект был чистым
stdlib.

## Сборка и проверка

```sh
go build ./... && go vet ./... && gofmt -l . && go test ./...
```

- Docker: `docker build -t gonginxlog:local .`
- GoReleaser без публикации: `goreleaser release --snapshot --clean`
- Реальный тестовый лог лежит в `tests/*.log` — он в `.gitignore` (не
  коммитится, это реальные production-данные пользователя, ~430МБ).

## О чём легко забыть

- `internal/tui` визуально проверить в headless-среде нельзя (нет
  `/dev/tty`). Логика/переходы состояний проверяются через
  `tcell.SimulationScreen` (`internal/tui/app_smoke_test.go`) — но
  внешний вид, цвета и "чувство" интерфейса подтверждает только
  пользователь в своём терминале.
- **Любое изменение в `internal/tui` (и вообще там, где несколько
  горутин трогают общее состояние) проверяй через `go test ./... -race
  -count=10`, а не просто `go test ./...`.** Обычный запуск ничего не
  покажет — гонку по map поймал только `-race` (см. DESIGN.md, раздел
  про crash 2026-08-12: `Aggregator.Report()` отдавал живой алиас на
  внутреннюю map вместо копии, плюс `reseed` звал `Report()` без
  блокировки — оба бага были невидимы без `-race`, а в проде уронили
  процесс fatal-ошибкой Go-рантайма, не перехватываемой `recover()`).
- `--nginx-conf` без указанного `--format-name` в конфиге — это
  осознанная ошибка, а не фоллбэк на встроенный дефолт (см. DESIGN.md).
- Не пушить в `main` и не создавать релизные теги без явной просьбы —
  это отдельные, ранее явно запрошенные действия каждый раз.
